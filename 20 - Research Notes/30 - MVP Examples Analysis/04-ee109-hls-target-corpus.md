## Acceptance conditions per example

Functional correctness is the required gate for the MVP. HLS performance is recorded only after functional output matches the source-level oracle.

| Example | Functional acceptance condition | Optional HLS performance note |
|---|---|---|
| `Lab1Part1RegExample` | With runtime args `3 5`, the generated kernel must produce the same `ArgOut` value as `gold = M + N`; the source checks equality and asserts the checksum (`Lab1Part1RegExample.scala:6`, `Lab1Part1RegExample.scala:20`, `Lab1Part1RegExample.scala:23-32`). | Record generated scalar ABI shape and HLS scheduling, but do not require a latency target for this scalar tracer. |
| `Lab1Part2DramSramExample` | For `N = 32` and runtime multiplier `3`, `getMem(dstFPGA)` must equal `src.map { _ * value }`; the source compares `dst.zip(gold)` with a reduced conjunction and asserts the checksum (`Lab1.scala:74`, `Lab1.scala:78`, `Lab1.scala:105`, `Lab1.scala:114`, `Lab1.scala:126-146`). | If HLS is run, record total cycles, inner-loop latency, and inner-loop II because the source comments name those metrics (`Lab1.scala:69-72`); functional array equality is still the gate. |
| `Lab2Part4LUT` | For runtime args, the generated result must equal `input + goldArray(i*N + j)` after reading the 3x3 LUT at `i.value, j.value`; the source asserts `gold == result` (`Lab2Part4LUT.scala:4`, `Lab2Part4LUT.scala:25-35`). | HLS should preserve the LUT as read-only local storage; exact LUT implementation style is secondary to the scalar result match. |
| `Lab2Part3BasicCondFSM` | `getMem(dram)` must match the exact 32-element gold array after the FSM writes and stores the SRAM; the source reduces elementwise equality and asserts the checksum (`Lab2Part3BasicCondFSM.scala:15-30`, `Lab2Part3BasicCondFSM.scala:31-37`). | HLS should emit structured state-machine behavior, but no performance target is required before exact array match. |
| `Lab3Part1Convolution` | The generated matrix readback must satisfy the source checksum: host `gold.map(...).reduce(_+_)` equals the `ids`-weighted output reduction, followed by `assert(cksum)` (`Lab3.scala:78`, `Lab3.scala:85-86`, `Lab3.scala:104-126`). | Record effects of `par` on load, shift, reductions, and store; functional checksum comes before matching requested II or partitioning quality (`Lab3.scala:39`, `Lab3.scala:44`, `Lab3.scala:56-64`, `Lab3.scala:74`). |
