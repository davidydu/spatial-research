## Macro/test harness boundary: what is core compiler input versus course harness

- `@spatial` is the macro boundary: `spatial.dsl` defines `final class spatial extends StaticAnnotation` whose `macroTransform` delegates to `spatial.impl`, and the companion tag names `SpatialApp` as the generated app base (`David_code/spatial/src/spatial/dsl.scala:28-38`). `SpatialApp` is `Spatial with DSLApp`, and `DSLApp.main` calls `compile(args)` (`David_code/spatial/src/spatial/SpatialApp.scala:1-5`, `David_code/spatial/argon/src/argon/DSLApp.scala:4-7`).
- The core compiler staging input is the block produced by `Spatial.stageApp`: it creates a `stageBlock`, stages `InputArguments()`, and calls the app's `main(args)` (`David_code/spatial/src/spatial/Spatial.scala:48-54`). `Compiler.stageProgram` logs rewrite and flow rule names to `0000_Staging.log`, calls `stageApp`, then returns the staged block (`David_code/spatial/argon/src/argon/Compiler.scala:100-113`; `David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0000_Staging.log:1-22`).
- `SpatialTest` is the regression/course harness around that compiler path: it supplies runtime-argument hooks and appends backend definitions including `CS217`, whose command-line flags target the CS217 synthesis/instrument/runtime flow (`David_code/spatial/src/spatial/SpatialTest.scala:9-13`, `David_code/spatial/src/spatial/SpatialTest.scala:80-88`, `David_code/spatial/src/spatial/SpatialTest.scala:151`). `DSLTest` backend parsing treats `PASS: 1` or `PASS: true` as pass and `PASS: 0` or `PASS: false` as fail (`David_code/spatial/argon/src/argon/DSLTest.scala:120-123`).
- For HLS, the core kernel is the `AccelScope` block: the first IR log shows the `AccelScope` has read memories `x5,x6`, written memory `x9`, and nested body statements `RegRead`, `RegRead`, `FixAdd`, `RegWrite` (`David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:90-149`). The `GetReg`, `PrintIf`, host `gold` add, `FixEql`, and `AssertIf` appear after the `AccelScope`, so they belong to the host oracle/test envelope (`David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:152-278`).
- The existing compiler has a broad pass and backend sequence, ending in tree, HTML IR, optional Scala, Chisel, C++, Rogue, resource, PIR, and Tungsten host generation (`David_code/spatial/src/spatial/Spatial.scala:146-164`, `David_code/spatial/src/spatial/Spatial.scala:220-252`). The MVP plan narrows this to a vertical EE109 path rather than the entire Spatial language or every existing backend (`Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:19-23`).

## Minimal IR nodes/metadata an HLS path must support

| Required support | Minimal requirement | Evidence |
|---|---|---|
| Staging substrate | Support a `stage(op)` model that creates symbols, computes effects, pushes symbols into scope/cache/impure state, records aliases, records consumers, runs immediate flow, runs registered flows, and checks aliases. | `stage` delegates to `register`, and `register` performs rewrite, effect computation, CSE, symbol creation, scope/cache/impure mutation, effects/alias metadata, consumer metadata, immediate flow, registered flows, and alias checks (`David_code/spatial/argon/src/argon/static/Staging.scala:93-153`, `David_code/spatial/argon/src/argon/static/Staging.scala:168-182`). |
| Type model | Support `Fix[TRUE,_32,_0]` as the Lab's `Int`, plus `Reg[Fix[TRUE,_32,_0]]` for `ArgIn` and `ArgOut`. | The DSL aliases `Int` to `argon.lang.Fix[TRUE,_32,_0]`, and the IR log types `ArgInNew`/`ArgOutNew` as `Reg[Fix[TRUE,_32,_0]]` (`David_code/spatial/src/spatial/lang/Aliases.scala:155-160`, `David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:43-89`). |
| Host ABI nodes | Support `ArgInNew`, `ArgOutNew`, `SetReg`, and `GetReg` to discover scalar inputs, scalar outputs, initial host values, and returned host values. | `ArgInNew`/`ArgOutNew` are allocation nodes, `SetReg` and `GetReg` are register transfer nodes, and the Lab IR uses exactly those nodes for scalar I/O (`David_code/spatial/src/spatial/node/Reg.scala:11-15`, `David_code/spatial/src/spatial/node/Reg.scala:49-61`, `David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:43-89`, `David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:152-160`). |
| Kernel boundary | Support `AccelScope` with one body block as the HLS top-level kernel region. | `AccelScope` defines a pipeline node with one pseudo-stage body and no counters, and the Lab IR records one `AccelScope` wrapping the four kernel statements (`David_code/spatial/src/spatial/node/Control.scala:21-31`, `David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:90-149`). |
| Kernel statements | Support `RegRead`, `FixAdd`, and `RegWrite` inside the `AccelScope` block. | The body block contains exactly two `RegRead`s, one `FixAdd`, and one `RegWrite` (`David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:102-149`). |
| Effects for ordering | Preserve read/write/simple/unique/mutable effects enough to keep host setup before kernel read, kernel write before host read, and the accelerator boundary alive. | The IR records `ArgInNew`/`ArgOutNew` as mutable, `SetReg` as read/write of the arg regs, `AccelScope` as unique/simple with reads and writes, `RegRead` as unique reads, `FixAdd` as pure, and `RegWrite` as read/write of the output reg (`David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:43-149`). `Effects` tracks unique, simple, mutable, reads, writes, and anti-dependencies (`David_code/spatial/argon/src/argon/Effects.scala:5-29`). |
| Block/control metadata | Preserve or reconstruct parent/block membership for statements inside `AccelScope`. | The nested `RegRead`, `FixAdd`, and `RegWrite` statements carry `DefiningBlk`, `ParentCtrl`, and `ScopeCtrl` metadata pointing at `x14` (`David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:112-149`). |
| Access metadata | Use `ReadMems`, `WrittenMems`, `Readers`, `Writers`, and `ReadUses` when available, or recompute the same facts from the node graph. | The IR records `ReadMems(Set(x5,x6))` and `WrittenMems(Set(x9))` on `AccelScope`, plus per-memory `Readers`/`Writers` and per-node `ReadUses` metadata (`David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:43-100`, `David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:104-149`). |
| Output shape | Emit a scalar HLS function equivalent to two scalar inputs and one scalar output pointer. | The tracer-bullet plan's initial C++ shape is `extern "C" void Lab1Part1RegExample_kernel(int argRegIn0, int argRegIn1, int *argRegOut)` with AXI-lite pragmas and `*argRegOut = argRegIn0 + argRegIn1` (`Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:220-234`). |

## What can be bypassed for the tracer bullet

- Bypass DRAM, SRAM, FIFO, LUT, RegFile, LineBuffer, `Foreach`, `Pipe`, `Reduce`, and `FSM` for this first bullet: the plan places Lab1Part1 at Stage 0 and lists only scalar argument, `Accel`, register read/write, and integer add for that stage, while later stages introduce DRAM/SRAM, LUT, FSM, and Lab3 memories/controllers (`Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:48-57`).
- Bypass full `SpatialTest` backend execution for HLS code generation: `CS217` is a `SpatialTest` backend configuration with synthesis/instrument/runtime flags and skipped make/run commands, while the HLS tracer target is a direct C++ kernel shape in the plan (`David_code/spatial/src/spatial/SpatialTest.scala:80-88`, `Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:220-234`).
- Bypass print/assert lowering inside the kernel: `PrintIf`, host `FixEql`, and `AssertIf` occur after `GetReg`, outside the `AccelScope`, and can become an external oracle that checks `3 + 5 == 8` (`David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:152-278`, `Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:236-242`).
- Bypass the current compiler's broad backend matrix for the first HLS path: existing `runPasses` can invoke Scala, Chisel, C++, Rogue, resource, PIR, and Tungsten codegens, while the MVP plan explicitly chooses a narrow EE109 vertical compiler path before full Spatial semantic cleanup (`David_code/spatial/src/spatial/Spatial.scala:146-164`, `David_code/spatial/src/spatial/Spatial.scala:220-252`, `Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:19-23`).
- Bypass controller scheduling features beyond `AccelScope`: `AccelScope` has no counters and exposes a single body pseudo-stage, and the Lab1Part1 IR body has no loop/counter nodes (`David_code/spatial/src/spatial/node/Control.scala:21-31`, `David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:90-149`).
- Bypass banking and local-memory configuration for this bullet: the Lab IR's global local-memory set is only the three scalar register-like host I/O memories `x5`, `x6`, and `x9`, and the plan makes dense DRAM/local memory/banking blocking for later EE109 examples, not for Stage 0 (`David_code/lab-1-accelerator-bandits-1/logs/CS217/Lab1Part1RegExample/0001_IR.log:280-282`, `Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:68-78`).
