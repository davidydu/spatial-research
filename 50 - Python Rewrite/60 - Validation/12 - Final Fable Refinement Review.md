## Unedited final response

Reviewing the current numbered documents, round-two dispositions and probe records as the third-round adversarial reviewer. No tools were used and nothing below is claimed as executed.

## 1. Verdict

**This is a defensible proposal to submit for professor approval. No adoption-blocking defect survives.** The two prior rounds and the Codex cross-review produced real repairs rather than wording changes: the underflow rule now uses the exact nearest-even threshold with an independently constructed oracle, the representation choice rests on ownership fit with bounded measurements as support only, and the protocol decisions separate the layers that earlier text had conflated.

I rederived the numeric claims by hand. The threshold `T = 2^emin - 2^(emin-P-1)` is the exact midpoint between minimum normal and its unbounded-exponent P-bit predecessor, and ties-even rounds that midpoint to the even significand, so strict inequality is correct. The root comparisons, the finite helper form `T = (2^(P+1)-1) * 2^(s-2)`, the sqrt and rsqrt width bounds, the Flt(3,2) examples at 7/8 and 15/16, and the interval counterexample `[29/32, 31/32]` all check out. The oracle described in R015 does not know `T` and does not read the stored bits, which was the round-one defect.

The remaining findings are two process gaps in gate placement, two small design omissions, one bookkeeping item and one optional preference. None contradicts the architecture, and none requires implementation to exist before submission.

## 2. Findings

**F3-01. Representation gate names a slice that cannot contain it.** Severity: medium, confirmed inconsistency. `PY-R017 - Compiler Representation Comparison.md:132` requires "the first adopted slice" to exercise task-group parent tokens and target-neutral planning. `04 - Python Implementation Roadmap.md:31` gives S1 no tasks and no planning. Tasks arrive at S5 (line 35) and planning at S6 (line 36). Counterexample: the team completes S1 exactly as written, declares the R017 gate passed, and S2 through S4 build on records whose task-group token-once rule and PlanRecords correspondence have never been verified. Smallest repair: rewrite gate 1 as staged obligations. S1 owns source, builder and import convergence, helper summaries, branch and loop yields, capability escape, alias and lifetime obligations, faults and malformed import. S5 owns task-group tokens. The bounded S6 plan on the S1 subset owns planning. Define "deep commitment" as S7 entry. Discriminating test: the completion audit rejects any "gate 1 passed" claim that lacks a linked S5 and S6 fixture ID.

**F3-02. The strongest dissent has no discriminating fixture before S9.** Severity: medium, gate-timing gap rather than contradiction. `PY-R017:128` says the use-heavy and remapping objection "justifies an early discriminating gate", but gates 1 through 4 never name one, and the roadmap places transformation work at S9 (`04 - Python Implementation Roadmap.md:39`). By then every family sits on the records. Counterexample: inline the same effectful helper twice and unroll a loop by four on the S1 kernel. The records route must mint fresh allocation-site and activation identities, remap captures, transfer requirement IDs and rebuild the use index. Nothing in S1 through S8 measures that cost or those invariants. Smallest repair: add one transform fixture to the S1 or S2 exit row with attributed index-rebuild, rewrite and verify timings reported against the R007 "ordinary optimization" budget, and preserve the Codex mutants: a stale proof keyed only by an unchanged operation ID, and one generation shared by two activations. Discriminating test: old revision byte-identical after a failed candidate, two activations with distinct lifetime state, every deleted operation's requirement either retained or discharged with a certificate.

**F3-03. Storage element capability for Index and MaskedVec is undecided.** Severity: low, design omission. `10 - Source Checker and IR Blueprint.md:136` says storage constructors take an element type, line 176 says runtime Index values are exact unbounded integers whose hardware width comes from a range contract, and line 180 forbids most MaskedVec uses until materialization. `PY-R018:57` defines ZeroImage for Bool, numeric, bits and aggregates but not for MaskedVec. `PY-R016:64` names `Reg[Index]` as a spelling without saying whether it exists. Counterexample: bare `r: Reg[Index]` with a loop-carried increment executes unbounded in the reference, has no portable ABI slot since the slot width is `ceil(W/8)` and Index has no W, and has no finite plan route. Bare `Reg[MaskedVec[4, Int]]` has no defined reset image: all lanes invalid, or valid zeros? Smallest repair: storage and port element descriptors require a Bits-capable value type. Index must pass through `embed` first. MaskedVec is storable only after `masked_materialize`, or ZeroImage(MaskedVec) is explicitly defined as all-invalid and the type is admitted. Discriminating test: both bare declarations reject with TYPE diagnostics while bare `Reg[Int]` accepts with image zero.

**F3-04. Partially written output buffers fault at completion, and the divergence is not recorded.** Severity: low to medium, omitted migration note. `40 - Package and Conformance Blueprint.md:108` requires all selected declared buffer-output cells initialized on Completed; `PY-R016:162` repeats this; `10 - Source Checker and IR Blueprint.md:217` fixes the scalar rule statically. Default views are whole-owner, so "selected" means every cell. Counterexample: a correct kernel writes the first half of a 32-cell `Out[Dram]` and leaves the rest untouched. The invocation faults even though nothing is wrong with the program. Original Spatial permitted partial DRAM output. Smallest repair: record this in D-28's deliberate-changes section and the Language Contract host section as a chosen divergence, naming the escape: bind `InOut` with an initialized backing, or add a declared written-region annotation later. Discriminating test: half-written `Out` returns Fault with a code naming the uninitialized region; the same kernel with `InOut` over `Backing.from_ints` returns Completed with untouched cells preserved.

**F3-05. Stale text and an in-progress source feeding adopted contract rows.** Severity: low, bookkeeping. `PY-R018 - Protocol Policy Refinement.md:7` carries `status: in-progress` and line 73 says disposition remains open, yet `30 - Python State and Protocol Contract.md:34,46,56` and the numeric contract adopt its policies. `10 - Source Checker and IR Blueprint.md:213` still says recurrence "requires `r:Reg[T]=reg(reset=...)`" and line 581 marks R001 E3's explicit `reg(reset=0)` as "Migration required", although the ZeroImage rule makes a bare `Reg[Int]` valid. Smallest repair: close R018 to `research-conclusion` after this round or tag the contract rows "pending R018 closure"; reword line 213 to "explicit or registered zero reset"; reclassify the E3 row as optional explicit reset. Discriminating test: a documentation lint fails any contract rule that cites an in-progress note, and the fixture corpus carries both bare and explicit `Reg[Int]` producing identical semantic records with different provenance.

**F3-06. Reversal condition 4 can only fire if someone builds the alternative.** Severity: low, optional preference. `PY-R017:135` reopens the default if a record implementation misses an R007 target "and a semantics-equivalent xDSL candidate meets it". No one has an incentive to build that candidate once the records exist, so the condition is nearly unfalsifiable. Discriminating test: the profile attribution report names representation, index and transaction cost separately so the trigger can be evaluated without argument.

Everything else I probed holds: the all-false consuming selector fault is confined to consuming selectors and does not touch pure selectors or vector masks; the abstract grant epoch versus physical clock rule admits the same-clock dequeue and enqueue case while retaining explicit-batch old-state semantics; the empty-fold, empty-lawful and empty-destination rules are consistent across R018, both blueprints and the numeric contract; the ExecutionProgram is bound to revision and lowering-table version with an independent direct-region oracle; the host program in R016 matches every signature in the package blueprint; the core package has no xDSL dependency and the pinned wheel is an optional extra.

## 3. Strongest credible alternative and what would reverse me

The strongest alternative is not xDSL as canonical semantic graph. The round-one probe already showed the framework verifier accepting use-before-definition, duplicated order tokens and mismatched yield arity, so the Spatial verifier is mandatory on either route and xDSL would contribute only storage, cloning, use-lists and printers. The credible alternative is a hybrid: canonical immutable records for the checked semantic program, with xDSL mandatory for the implementation plan from S6 onward. The plan layer is where multi-block control, large unrolling and remapping, and any external MLIR-based HLS pipeline would live, and where mature use-list maintenance and region cloning have the most value. The proposal's own dissent paragraph is essentially this argument.

I still recommend the proposal as written, because PlanRecords share the ownership and publication rules of the semantic records, a second discipline would appear exactly at the layer with the least implementation evidence, and no named pipeline exists to reuse. Three outcomes would reverse that recommendation:

- **A required plan transform** such as banking, retiming or continuation splitting cannot be expressed in closed PlanRecords without a mutable second authority. This is R017's condition 4a and the F3-02 fixture is the earliest place it would surface.
- **The integrated S1 or S6 measurement** misses an existing R007 target with the miss attributed to record index rebuild or transaction cost, and a semantics-equivalent xDSL candidate meets the same target under the same correctness guarantees.
- **A named external pipeline** demonstrates a whole-workflow benefit after conversion, correspondence, provenance and startup costs are charged, as gate 3 requires.

A slow exact-rational reference at S3 would not reverse the architecture; it would call for approximation profiles and attributed profiling first, as D-28 already states.

## Final architecture for the professor

Kernels are ordinary Python syntax read as text and never executed, checked by a Python compiler that owns every typing, numeric, effect and protocol rule, and run by a Python reference simulator that produces exact values and committed-effect traces with structured diagnostics. The checked program and its later hardware plan are canonical immutable Python records with one verification and publication boundary, and any framework representation is a derived, optional adapter that can never define meaning. Hardware follows from that checked plan through a Python-executed protocol runner into AMD Vitis HLS C++ on a locked release, device and clock, with every target capability reported as supported, missing or unverified rather than assumed.
