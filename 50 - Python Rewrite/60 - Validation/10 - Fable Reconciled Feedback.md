**Verdict: retain the proposed architecture, and adopt it only after a bounded set of contract corrections.** Under the stated assumptions (pure Python frontend, compiler and reference simulator, no Rust core, full-language scope preserved, research before implementation), the design is coherent and the three reviews found no defect that reopens the Python direction. The core that stays is: raw-source acquisition as the acquisition core, one checked semantic program feeding both the simulator and the planner, a Spatial-owned verifier over closed registries, the fold/lawful/tree split, ordered effects with lazy branches, bounded ordered queues distinct from communicating channels, the lifetime table, and progress refinement for hardware. What must change before S0 is narrower than any single review claimed. One numeric rule is provably wrong against the oracle the package names (N-01, now independently confirmed by the manager). Several documents disagree in text on signature binding (L-F01), on the built-in law set (A-F11 wording), on a Bool conversion rule (S-N04), and on LineBuffer width notation (S-S01). Two protocol rules are ambiguous rather than wrong (S-P01, S-P02). Everything else in the reviews is either a surface-usability adoption question for the professor, a measurement gate, or an overstatement that this reconciliation corrects. Maintenance scarcity plays no role in any decision below.

## Decisions, plan, and limits

**Core architecture, stays.** Python-owned semantics with the vendor as scheduler. Raw-source acquisition as the core, with a possible prevalidated-loader adapter later. One checked program for simulator and planner. Spatial verifier over single-block regions and linear tokens. Three reduction operations with identity, seed, reset and destination kept distinct. Ordered queues fault and channels wait. Progress refinement alongside trace safety. Closed registries with capability diagnostics instead of silent downgrades.

**Surface usability, professor decides.** Type constant spelling (L-F02). Expression lambdas in DefinitionRef slots (L-F06). Declared-uninitialized value merge (L-F05). Scalar write syntax (L-F07). Implicit checked embed as sugar (L-F04). Float-to-fixed default (S-N02). Adoption tiers (S-A01). My recommendations: adopt L-F02 and L-F06 lambdas, decline L-F05 and L-F04 for the first release, keep bare port assignment, keep documented cast defaults, present tiers without removing families.

**Implementation choices, team decides.** Reduction domain spelling, task auto-naming, kernel-handle wrapper names, notebook session registry, pin update policy, warning on stop-sensitive `par`, Bool conversion wording, Reg default image, admitted combine ID list.

**Strongest competing pure-Python architecture.** One persistent immutable custom IR of frozen records with explicit regions, binders, order tokens and effect summaries, verified by the same Spatial checker and consumed directly by the interpreter and planner. Its advantages are native immutability and one hashable identity. Its cost is a hand-written rewriter and printer. The documents already make this the named fallback at `40 - Python Compiler and HLS Contract.md:39`. The exact measurement that should decide: build the S1 kernel path's checked IR on both substrates behind the Spatial-owned API boundary (`40 - Package and Conformance Blueprint.md:43`), run the predeclared R007 workloads at `PY-R007 - Host Workflow Reproducibility and Validation.md:94-101` with their stated warmups and repetitions, and report the attributable clone, verify and publish share of each pass transaction, plus the count of generic rewrites S1 actually uses. Decision rule: use the already declared targets, not new thresholds. If xDSL's attributable share causes a target miss that the custom records avoid, switch at S1. If neither misses, keep xDSL as proposed. Neither substrate is claimed faster or more correct before this measurement.
