## Purpose and status

Account for the full original Spatial research base while designing the Python rewrite. The introductory programs do not limit the scope. This ledger supports R04 in [[03 - Managed Research Execution]] and PY-Q009 in [[02 - Python Open Questions]].

**Current status: proposed research crosswalk.** All 106 original `type: spec` documents have a substantive family destination and explicit disposition in [[PY-R005 - Full Language Coverage and Migration]]. These are design obligations for professor review, not adopted semantics, implemented support, or HLS eligibility. IDs and original-document links are preserved from the inventory at vault revision `7a15c26`; current note corrections update evidence, not feature counts.

P = preserve intent; R = deliberate revision; I = replace infrastructure; B = reference-only old backend/target mechanism. Combined codes distinguish a mechanism from its language responsibilities. Each row names the obligation/revision; R005 supplies its representation, intended lowering and discriminating gate. A B disposition never erases a language capability.

Stages use shared S0–S9 IDs in [[04 - Python Implementation Roadmap]]. The row lists semantic/research integration slices; target planning/validation also requires the family-specific S6–S8 duties in R005. Gates G01–G18 are defined under corresponding R005 family headings. Listed slices are intended placement, not completed milestones. Later evidence records must preserve research dispositions while separately reporting reference implementation, target lowering and validated capability.

## Source-family gap check

Pinned `spatial@e7a8f2f7f776dd0c5ac7fc03f16b3ed4d97021f0` contains 58 `src/spatial/lang/` and 33 `src/spatial/node/` files, plus 24 Argon language and nine Spatial library files: **124 paths**. R005 assigns each path once to a primary substantive family. Numeric/math nodes, `src/spatial/math/LinearAlgebra.scala`, passes, emulator/executor, models/polyhedral services and Fringe are additional evidence followed through the document rows.

The check includes generic scalar/aggregate/packing/math/RNG/debug; domains/FSM/forever/folds/timing; views/init/shifts/windows/dynamic allocation/dense/sparse transfer; queues/arbitration/merge/locks; independent stream fields versus atomic records, frames/buses/components; ordinary host arrays/tensors/files; libraries/lexical guards; conservative banking/retiming; models/DSE/ABI/target replacement. R005's scope choices and revisions require professor review. No original simulator/backend is universally authoritative.

## Closure requirements

Research accounting is populated; adoption and executable evidence remain open. Every claimed implementation level must link an adopted contract/profile, composed accepted programs and negative cases, independent expected values/traces, and the appropriate reference/plan/vendor/RTL/device result. E1/E2/E3 alone cannot close advanced families. A capability rejection names its stage/profile obligation and preserves the full-language representation contract.

[[PY-R006 - Compiler Architecture and Framework Choice]], [[PY-R008 - Advanced State and Communication Protocols]], [[PY-R007 - Host Workflow Reproducibility and Validation]], and [[PY-R009 - HLS Boundary and Control Lowering]] provide draft proposals, not executed Python/HLS support. Later vendor memory/scheduling/numeric research supplies refinement evidence rather than silently choosing semantics in an emitter.
