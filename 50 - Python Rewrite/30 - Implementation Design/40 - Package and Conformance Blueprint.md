## Purpose

This proposed implementation design closes interfaces left to S0 in [[04 - Python Implementation Roadmap]]. It refines [[D-28]] and [[PY-R007 - Host Workflow Reproducibility and Validation]]. It specifies what contributors will implement after approval; none of the package below exists yet. The independent audit is [[07 - Python Implementation Readiness Audit]]. [[PY-R017 - Compiler Representation Comparison]] motivates the 2026-10-03 proposed record-based core and optional xDSL adapter, superseding the earlier mandatory-framework package assumption.

## Repository and module ownership

Use a new repository with working project name `spatial-python`, import package `spatial`, and a `src/` layout. These are local project names, not a claim of available or published package-registry names. Keep Scala and Rust repositories as reference checkouts. The documentation vault remains the authoritative reviewed design; the implementation repository links to the exact adopted document revision and includes executable fixtures and implementation records.

| `source/` | Source units, manifest resolution, token/AST normalization, grammar, frozen meta specialization | `schema` |

| `cli.py`, `diagnostics/` | Command/API projection and common structured diagnostics | Public host API and immutable records |

Test folders mirror boundaries: `tests/{source,check,numeric,protocol,runtime,passes,artifacts,plan,hls,composition}`. Keep data-only expected results in `tests/fixtures/`; separate vendor tests under `tests/vendor/`. `tools/conformance.py` reads the manifest below. `profiles/` contains versioned semantic and target descriptors, and `locks/` contains exact dependency/tool manifests. Documentation examples are copied into fixtures with source-document revision and example ID so drift is visible.

No module retrieves a global current compiler, interpreter or target. A compilation context owns immutable registries plus per-revision analysis caches. An invocation owns mutable execution state. The checker creates the owning accepted immutable record revision through the source blueprint's full publication gate; neither a frozen dataclass nor an imported checked flag certifies a candidate. RecordIndex/use maps, analyses and derived ExecutionProgram caches belong to exact revisions in the compilation/runtime context, never to shared graph nodes. A frozen record API is an ownership discipline for trusted compiler code, not a sandbox for arbitrary Python. The checker may share numeric functions with runtime, but acceptance oracles are separate. Code review checks this dependency direction and rejects circular imports resolved through ambient mutable state.

## Public workflow and failures

The following names are the proposed host API. [[PY-R016 - Source and Host Workflow Refinement]] records the alternatives and the 2026-10-03 constructor/output refinement; [[PY-R012 - Lab1 Syntax and Host Mapping]] supplies the complete ordinary Python driver. Kernel syntax and its registered operations are defined in [[10 - Source Checker and IR Blueprint]]. Successful calls expose frozen data/program handles or immutable result records, never mutable IR objects. `capture`/`specialize` return their value directly and raise the public `DiagnosticError(diagnostics)` on expected source/specialization failure; they never return a partial value after that exception. This preserves the previously specified direct-return signatures. `check`/`prepare` keep their existing Ok/Error results. Uniform Result returns could simplify a later API revision, but are not silently substituted in this proposal.

| Call | Input and result |
|---|---|
| `capture(bundle)` | A `CaptureBundle` containing the entry module/export and all source/dependency contents → syntax-validated `Template`. No source execution or semantic support claim |
| `specialize(template, meta)` | Exact named frozen values → `UncheckedProgram`; validate reachable source grammar before static branch elimination |
| `check(program, profile)` | Unchecked program and semantic profile ID → `Result[CheckedProgram]`; profile distinguishes guarded reference validity from statically discharged requirements |
| `prepare(program, bindings, session=None)` | Checked program, typed port/environment descriptors, optional exclusively owned session → `Result[Invocation]` |
| `simulate(invocation, environment, budget)` | One prepared invocation or saved continuation → `RunResult`; budget includes steps, numeric work and trace storage |
| `plan(program, target, binding_contract)` | Checked meaning, target descriptor and invocation-specialization assumptions → `Result[ImplementationPlan]` |
| `emit(plan)` | Verified eligible implementation plan → `Result[Project]` with file bytes, hashes, source maps and manifest |
| `validate(project, toolchain)` | Generated project and explicit installed toolchain → evidence records with commands, exit status and report hashes |
| `export_artifact(value)` / `import_artifact(bytes, registry)` | Canonical data format below; import reconstructs a candidate and verifies it, never trusts a stored checked flag |

`Result` is either `Ok(value, diagnostics)` or `Error(diagnostics, inspectable_partial=None)`. A failed plan can be inspected but cannot be passed to `emit` or reused as an eligible cache entry. Internal exceptions become `CompilerFailure` with reproduction IDs; they never masquerade as an ordinary source diagnostic. Public argument misuse receives a structured `HOST.INVALID_ARGUMENT` diagnostic: closed data constructors and direct-return acquisition/specialization raise `DiagnosticError`, while Result-returning calls return `Error`. A wrong dtype/shape/port binding receives its specific HOST diagnostic in `prepare`. Unexpected process termination remains a failed tool execution.

`RunResult` has `outcome`, `complete_outputs`, `partial_state`, `trace`, `continuation`, `diagnostics`, and `run_identity`. Its closed public outcome strings and payload obligations are the following table. Snapshot means a frozen inspection record of committed state, initialization/generations, pending requests and outstanding obligations; it is not output-completion authority. A continuation additionally contains validated resumable control/helper state. Trace, diagnostics and run_identity are always present, possibly with an empty trace/diagnostic tuple.

| Exact outcome | Meaning | complete_outputs | partial_state | continuation |
|---|---|---|---|---|
| `Completed` | Successful completion, required cleanup/quiescence and output initialization checks passed | Frozen mapping of declared Out/InOut snapshots; may be empty for a no-output interface | None | None |
| `Fault` | Semantic/protocol fault after its required cleanup is quiescent | None | Snapshot with fault and committed prefix | None |
| `Cancelled` | Requested cancellation finished its required cleanup | None | Snapshot with committed prefix | None |
| `Stopped` | Declared stop/exit ended work and required cleanup, without successful output publication | None | Snapshot with stop reason and committed prefix | None |
| `End` | Closed/exhausted input propagated as an unhandled invocation termination under the declared protocol, after cleanup | None | Snapshot with endpoint/end cause | None |
| `WaitingEnvironment` | Concrete dependency path to an allowed external event can enable progress | None | Snapshot with dependency path | Execution/drain continuation |
| `QuiescentUnknown` | No enabled transition is known, but enabling/deadlock evidence is insufficient | None | Snapshot with unresolved dependency/analysis | Execution/drain continuation |
| `BudgetExhausted` | A configured observation, trace, aggregate numeric-work or per-helper numeric limit stopped unfinished work | None | Snapshot with named limit, usage and retained helper/request state | Execution/drain continuation |
| `Breakpoint` | Registered debug observation paused after its event | None | Snapshot at the next continuation point | Execution continuation; resumption does not repeat the breakpoint event |
| `Deadlock` | A certified closed blocked component prevents invocation progress | None | Snapshot with wait-graph certificate and affected component | Control-only continuation for declared cancellation/drain; cannot resume ordinary work in the unchanged closed state |

The state blueprint's existing Completed/Fault/Cancelled/Stopped/End/WaitingEnvironment/QuiescentUnknown/BudgetExhausted/Deadlock names are preserved; Breakpoint supplies the exact tag for its previously named observation pause. An endpoint-level End that the kernel handles is not itself a terminal RunResult: that program may continue and later return Completed. A graceful stop policy that permits successful publication must satisfy normal completion and return Completed, not attach complete outputs to Stopped.

A requested Fault/Cancelled/Stopped/End does not authorize abandoning external obligations. If cleanup cannot finish within the environment/budget constraints, return the applicable incomplete outcome above and retain `pending_terminal` plus its original cause in the snapshot/continuation. Resume preserves the declared termination mode and permits no new controller/body admission. A graceful pending Stopped may still finish effects of already admitted bodies before draining; it must not skip their remaining user operations. Fault/cancellation follows its declared checkpoints and cleanup policy without restarting abandoned work. Once a continuation has entered terminal drain, it runs only its retained obligations/cleanup. Only quiescent completion publishes the pending terminal tag. Deadlock continuations likewise allow cleanup control, not an invented enabling event. Session ownership stays held until the declared protocol is quiescent. Session serialization requires a quiescent checkpoint or complete representation of every outstanding request/environment obligation.

The numeric engine's **internal** `ResourceLimit` maps to outer `BudgetExhausted`, with a diagnostic identifying operation/request, limit name, used amount and active cap. It is not another public outcome and not a language Fault. Retain the NumericHelperState immediately before its next unperformed budget-checked action, earlier committed input/RNG effects and pending ownership; resumption with larger limits continues that state without replaying effects. Aggregate numeric_work exhaustion uses the same outer tag but identifies the aggregate counter. Successful helper completion alone does not publish invocation outputs.

`simulate(continuation, environment, budget)` resumes the same invocation under validated permitted environment input and explicit budget replacement. Budget caps are cumulative over the retained invocation counters (helper sublimits over that retained request); a lower cap than already used rejects as HOST.INVALID_ARGUMENT. Increasing steps/numeric_work does not silently raise per-helper limits. `numeric_limits=None` on resume retains the already frozen sublimits; an explicit ReferenceBudget replaces them after validation. Run provenance records the prior continuation/run identity and new cap values. A malformed/mismatched continuation, incompatible environment or invalid host argument raises DiagnosticError before further transitions. Unexpected implementation exceptions raise CompilerFailure with a reproduction identity, outside this semantic outcome union. Actual process loss/OOM need not produce any RunResult.

The CLI mirrors these calls as `spatial check`, `simulate`, `plan`, `emit`, `validate`, and `inspect`, added with their real feature slice. Structured stdout is one JSON result; human logs go to stderr. Exit 0 means that command's requested stage succeeded, 1 a source/invocation/runtime failure, 2 an unmet capability/requirement, 3 a vendor or external failure, and 4 a compiler defect. A successful `emit` never claims RTL validation. Host observation limits return an explicit incomplete outcome, not success or a deadlock proof.

## Public source, input and output constructors

All forms below are **proposed and unimplemented** public exports of the host package `spatial`. Importing that package is ordinary host Python; it does not load a captured kernel as a Python module. Constructors recognize exact closed record types and exact builtin payloads, never user conversion, attribute, iterator or serialization hooks. Immutable snapshots contain no live Python callback.

| Public signature | Validation and frozen record |
|---|---|
| `SourceUnit(*, module_id, text, label)` | Exact builtin strings, valid Unicode scalar text; enforce configured acquisition byte bounds before encoding/tokenization/parsing; source identity is module ID plus exact UTF-8 digest. Freeze admitted text/line map, then normalize tokens only after capture also validates the aggregate bundle budget. Label is display provenance, not a fabricated file span. SourceRef spans are derived from the acquired text; adapters supplying generator/cell origin maps use the same checked origin schema |
| `core_prelude()` | Return the installed frozen core registry descriptor with its exact version/digest; capture records it, never rereads ambient names. Reproduction imports the recorded bundle/descriptor and rejects unavailable/mismatched versions |
| `CaptureBundle(*, entry, sources, dependencies, prelude)` | Entry is the exact `(module_id, export_name)` string tuple; sources is a tuple of SourceUnits; dependencies is a tuple of frozen manifest records. Reject duplicate/conflicting module IDs, missing imports, bad exports or registry mismatch. Empty dependencies is valid for a core-only source module. Grammar/profile versions come from the recorded registry, not caller globals |
| `ScalarInput.from_int(*, dtype, value)` | Dtype is a registered integral Fix descriptor such as Int; value is exact builtin int within that type's range. Reject Bool, subclasses, float, implicit wrap/saturation; freeze typed raw bits |
| `IndexInput(*, value)` | Exact builtin int preserved as mathematical structural data, with no hardware-bit encoding. Check port category and all shape/bound preconditions during prepare |
| `Backing.from_ints(*, name, dtype, shape, values)` | Exact strings/tuple extents/tuple integer values; integral Fix dtype, nonnegative extents and exact row-major element count; range-check every value. Freeze portable ABI bytes, logical owner shape and all-cells-initialized state |
| `Backing.empty(*, name, dtype, shape)` | Registered Bits-capable byte-storable descriptor and closed nonnegative shape; budget shape arithmetic, payload bytes and logical initialization/state representation before expansion. Zero physical bytes and **no initialized logical cells**. A zero-bit element still has logical cells and initialization |
| `backing.view(*, access)` | Access is exactly `read`, `write` or `readwrite`; produce a whole-owner contiguous BufferView with explicit dtype/shape/byte-offset/byte-strides and logical coordinate map. Multiple views retain the same owner ID and initialization state |
| `Environment.closed_memory()` | Frozen environment registration for deterministic local-memory completion without stream/device/foreign input; incompatible requested environment behavior diagnoses. No future event is guessed |
| `ReferenceBudget(*, max_integer_bits, max_rational_ops, max_series_terms, max_refinements, max_certificate_nodes)` | Exact nonnegative administrative integers in the numeric blueprint's closed schema; explicit per-helper sublimits, not a numeric semantic format |
| `Budget(*, steps, numeric_work, trace_bytes, numeric_limits=None)` | Nonnegative exact administrative integers; numeric_work is aggregate evaluator fuel. Numeric_limits is a ReferenceBudget or None, which initially resolves the registered bounded execution configuration and on resume retains the frozen limits. Snapshot every limit/configuration ID in invocation/run provenance. Any configured limit stops with public BudgetExhausted and a continuation, never Completed or a separate outer ResourceLimit |
| `ScalarOutput.to_int()` | Completed scalar integral Fix record → exact signed/unsigned integer; expose dtype and canonical bits. Nonintegral format rejects without rounding |
| `BufferOutput.to_ints()` | Completed buffer integral Fix record → exact tuple in row-major logical order; expose dtype, shape and immutable typed contents. Nonintegral format rejects |

A plain exact builtin dictionary maps port names to input/view records in `prepare`; it is copied and validated, never retained as mutable invocation state. Bind every In/InOut scalar, every memory port including Out buffers, and every required environment descriptor. Scalar Out ports require no binding/seed and supplying one rejects. Unknown, missing or incompatible names/types reject before execution. Python objects, arrays and buffer inference are optional adapters, not coercions in this core API.

The convenience Backing factories create canonical contiguous owners. The existing explicit BufferView record route represents other checked views and formats; it must supply both the logical coordinate map and physical byte mapping. Zero-width elements cannot be distinguished by byte offset, so a byte-only view is insufficient. For Bits(0) or empty aggregates, a huge logical shape can have zero payload bytes while still requiring shape/coordinate arithmetic, initialization/capability/lifetime state and alias checks. Backing construction and prepare budget that work before enumerating cells or expanding maps; symbolic representations are allowed, but zero-byte storage never proves initialization or disjointness. Exceeded host construction limits raise DiagnosticError(HOST.RESOURCE_LIMIT); preparation limits return Error with that code. These are administrative resource limits, not a new arbitrary maximum language shape. Initial logical cell state belongs to the owner. Separate backing objects with the same name conflict within one preparation registry; views of one owner preserve aliasing. Copy each backing once when preparing reference execution and rebuild every view on that copy. The typed factories freeze input bytes; an explicit mutable-owner adapter is snapshotted at prepare under the same rule.

Complete outputs read **invocation snapshots**, not the caller's original allocations. The default copied preparation does not promise copy-back to the host `Backing`. On Completed, all logical cells selected by each declared Out/InOut view and all scalar outputs must be initialized. Otherwise completion produces Fault with `HOST.OUTPUT_UNINITIALIZED`, phase `completion`, the output port/view and a bounded description or witness of its uninitialized logical region; it publishes no complete output map. Initialization belongs to the owner: a write-only Out view does not erase existing initialization or change overlapping views' state. Thus half-writing an Out over Backing.empty fails when any selected cell remains uninitialized, while half-writing an Out over Backing.from_ints may complete with untouched initialized cells preserved. Out still forbids kernel reads; InOut is needed when the kernel reads old contents. Writes through a valid alias initialize the same owner cells. Completion checks precisely the selected view, not inaccessible cells elsewhere in its owner. A view with zero logical cells satisfies this buffer check vacuously; nonempty zero-bit cells still require initialization. Fault/cancel/stop/budget results retain earlier committed effects only in partial_state. A decoder cannot accept a partial-state record as a completed output. Partial progress and a correct-looking prefix never authorize PASS.

These constructors supply a complete student path without changing `capture → specialize → check → prepare → simulate`. For example, the Lab 1 fixed tile binds `Backing.from_ints(name="input",dtype=Int,shape=(32,),values=tuple(range(32)))`, `ScalarInput.from_int(dtype=Int,value=2)` and `Backing.empty(name="output",dtype=Int,shape=(32,))` through their read/write views. Binding a `(31,)` output view returns `Error` with `HOST.SHAPE_MISMATCH`, port dst, expected `(32,)`, actual `(31,)`, and the related source declaration. An out-of-range scalar constructor raises `DiagnosticError(HOST.INVALID_ARGUMENT)` before preparation. The paired cases and exact complete host listing are in R012/R016.

Supporting another Python minor requires the grammar/capture and artifact suite; xDSL's wider declared support does not establish Spatial support. Deployment platform support is separately tested; this baseline is not a claim that every operating system has been validated.

The proposed core runtime uses CPython and the standard library for the canonical record/checker/numeric/protocol path; xDSL and its dependencies are **not mandatory core dependencies**. Use `setuptools.build_meta` with the recorded `setuptools==84.0.0` build pin and a static Spatial package version; this build tool is not an imported compiler/runtime dependency. ## Canonical data format

Define **SpatialJSON-v1**, an explicitly restricted format, not an assertion of compliance with another canonical-JSON standard. The allowed tree contains exact builtin strings, Booleans, null, lists, and string-keyed objects. JSON number tokens are forbidden. Every structural integer is a canonical decimal string (`0` or optional minus followed by a nonzero leading digit); negative zero and leading zeros reject. Semantic integer values use `{"kind":"integer","value":"-3"}`. Typed bits use `{"kind":"bits","type":"t0","hex":"ff"}` with exactly `ceil(W/4)` lowercase hex digits and zero unused high bits. MaskedVec records retain a validity vector and canonical zero payload for inactive lanes, which remain unreadable until guarded extraction or explicit materialization. Unchecked artifact pending attachments are rechecked against the frozen effect ledger, including dropped/duplicate leaves. Rationals use reduced signed numerator and positive denominator strings. Floats use typed bits, preserving signed zeros and NaN encodings; host JSON floats never carry numeric semantics.

Schema field names are ASCII identifiers. User strings retain exact Unicode scalar values; reject lone surrogates and do not normalize source/provenance text. Arrays preserve semantic order. Objects sort keys by ASCII order. Encode UTF-8 with no BOM or trailing newline, no whitespace between tokens, compact JSON separators, literal Unicode and ordinary JSON escaping of quotes, backslash and controls. This is precisely `json.dumps(tree, ensure_ascii=False, sort_keys=True, separators=(',', ':'), allow_nan=False).encode('utf-8')` **after** recursive exact-type/schema validation. No `default` callback or user object's serialization method is called.

Decoder requirements: enforce byte, nesting, object-count and string-length budgets; require UTF-8; reject duplicate keys through `object_pairs_hook`; reject raw number tokens through `parse_int`, `parse_float` and `parse_constant`; validate all tags/fields/IDs and re-encode to require canonical bytes. Limits produce `ARTIFACT.RESOURCE_LIMIT`. Huge decimal integers use bounded chunk conversion rather than changing the interpreter's process-wide digit limit. Re-encoding is not a substitute for semantic or reference validation. Python's [JSON documentation](https://docs.python.org/3.14/library/json.html) documents the decoding hooks and nonfinite-value behavior; those hooks support this stricter project format (accessed 2026-10-01).

An artifact envelope has exactly `schema`, `kind`, `payload`, `provenance`, and `dependencies`; unknown fields or major versions reject. Each kind defines a closed payload schema. Optional fields are explicitly null rather than silently omitted. Human pretty printing is an export view, not canonical bytes.

| Kind / schema ID | Required payload fields |
|---|---|
| Template / `spatial.template/1` | `entry`, `source_units`, `dependency_manifest`, `grammar_version`, `meta_formals` |
| Unchecked / `spatial.unchecked/1` | `profiles`, `definitions`, `exports`, `entry_id`, `meta_snapshot`, `dependency_refs`, `symbols`, `origins`, `requirements_requested`, `pending_attachments`; nested region/expression records from the source blueprint |
| Semantic / `spatial.semantic/1` | `exports`, `types`, `functions`, `resources`, `profiles`, `requirements`, `model_refs` |
| Plan / `spatial.plan/1` | `semantic_digest`, `target_digest`, `binding_contract`, `machine_graph`, `storage_plan`, `numeric_realizations`, `abi`, `constraints`, `correspondence`, `obligations` |
| Project / `spatial.project/1` | `plan_digest`, `files`, `entry_symbol`, `build_recipe`, `toolchain_requirements`, `source_map`, `capabilities` |
| Invocation / `spatial.invocation/1` | `semantic_digest`, `port_bindings`, `backings`, `session_state`, `environment_contract`, `initial_rng`, `budgets` |

The `spatial.run/1` payload keeps its existing `outputs` key: it is the canonical serialization of public `RunResult.complete_outputs` when outcome is Completed, and exactly JSON null for every other outcome. Each completed entry encodes its registered scalar/buffer snapshot schema, dtype, logical shape where applicable, and exact typed contents. Import validates that the outcome/output combination is consistent, that all required declared Out/InOut snapshots are complete and initialized, and that their descriptors match the invocation interface. Import also validates the exact outcome/partial_state/continuation matrix above, including pending-terminal and control-only restrictions. Non-Completed with non-null outputs, or Completed with missing/incomplete outputs, rejects; import never promotes partial_state or physically zero-filled storage into completed output authority. The public decoder reads only the validated complete-output projection.

The frontend blueprint defines function/operation/type records; numeric and protocol blueprints define their payloads; the table above fixes their containers. Each nested record carries a registered tag and schema version, not arbitrary dictionaries. Type tables sort canonical descriptor bytes. Exports retain declared ABI order; reachable private functions are numbered by deterministic first-use traversal from those exports. Blocks, operations and arguments use preorder positions with explicit operand/result indices. Local user names and source offsets are provenance. No process address, Python object hash, absolute path or xDSL pointer enters canonical semantics. This canonicalizes the same normalized ordered graph and alpha-renamed locals, not all mathematically equivalent programs.

Import order is bytes → strict tree/schema → unresolved candidate records → exact ownership/ID/type/reference validation → full Spatial verifier including profile/model checks and obligations → trusted construction/publication of the owning checked immutable revision. Freezing fields is an intermediate ownership operation, never the validation result. Canonical PlanRecords additionally require the plan/correspondence verifier before eligibility. A hash or signed cache entry never substitutes for that verifier. A failed or unknown requirement remains ineligible at the corresponding stage. Recompute rather than deserialize analysis/use indices or ExecutionProgram caches initially. Optional xDSL text/bytecode is not a SpatialJSON semantic/plan artifact; it must pass the registered adapter conversion and canonical-record verification route.

## Identities, cache transactions and provenance

Use SHA-256 over `b'spatial/' + kind + b'/1\x00' + canonical_payload_bytes`. Kinds domain-separate acquisition, semantic, plan, build, invocation, run and provenance. Acquisition includes exact source/dependency contents and parser identity. Semantic identity includes canonical meaning, profiles, admitted invocation requirements and foreign-model code/dependency digests. Plan adds target/binding assumptions. Build adds compiler/framework versions, pipeline/options, helper contents, generated files and tool profile. Run includes exact typed input backing snapshots, session/RNG state, environment events and scheduler/budget identity. An incomplete environment records an open tail; its prefix never identifies a completed run.

Paths, labels, source text and expanded origin chains belong to a separately hashed provenance table keyed by canonical node IDs. Semantically equal artifacts can share checked meaning while diagnostics bind to their own provenance. A cache lookup never attaches another user's source map merely because semantic digests match. Public API/export names and external ABI names remain semantic when renaming them changes the interface. A checked revision key combines accepted semantic and provenance identities with schema/registry/profile/checker-rule identities; record indices and analysis/execution caches must bind that exact revision, not only a shared operation ID. Derived ExecutionProgram keys additionally include executor/schema versions. No public API exposes a mutable candidate or index as an accepted revision.

Publish a cache entry only after its stage completes: write a unique temporary directory, validate file hashes/manifest, then atomically rename on the same filesystem. Readers require a complete manifest and check all referenced hashes. Cache keys include every upstream dependency; a missing optional model/profile is a cache miss or diagnostic, not a guessed replacement. Concurrent writers of identical bytes may converge; differing payloads under one key are a compiler/storage defect. Never unpickle or import code from an artifact.

## Buffers, packing and session ownership

`Backing` explicitly owns bytes/bytearray plus an invocation-local ID. `BufferView` has backing ID, byte offset, shape, byte strides, element type, access capability and logical origin. Core constructors take explicit descriptors; automatic NumPy/memoryview inspection belongs to an adapter. One preparation registry identifies common owners across views. Unknown owner/offset cannot establish disjointness; an adapter must provide a checked mapping or make an explicit copy and retain its changed alias contract.

For a nonempty view, check the minimum/maximum reachable byte address using each `(extent-1)*stride` contribution and the element slot width. Empty dimensions perform no element access. Negative/zero strides are representable; writable overlap requires the declared alias/order contract. An interval-overlap test is conservative: it cannot prove overlap or disjointness of all strided sets. Use exact finite enumeration under a budget or the verified affine method; otherwise retain `unknown` and reject a requested disjointness precondition. Copy each backing allocation once for default reference preparation and recreate every view on that copy. Do not snapshot each port separately.

The byte-backed Backing/BufferView route requires a registered Bits-capable element descriptor, recursively through aggregates. Index and MaskedVec have no implicit byte slot; their use here raises DiagnosticError(HOST.DTYPE_CAPABILITY) in a factory or returns that diagnostic in prepare for an explicit invalid view. Exact IndexInput scalar ingress is a separate structural record, and private reference typed cells retain exact Index or MaskedVec values under the source/state capability ledger. A MaskedVec runtime/artifact record carries validity; serialization is not authorization to bind it as a packed buffer or queue payload. Use explicit embed or masked_materialize and check the resulting Bits capability. A target's private Index/mask layout requires its own checked range and representation proof.

The portable host ABI for Bits-capable values uses little-endian bytes, one `ceil(W/8)`-byte slot per scalar/aggregate element, with unused high bits zero. Aggregate fields in declaration order and vector element zero occupy successive low-bit ranges; nested layout recurses. Packed off-chip hardware words have a separate physical mapping and cannot silently change this host ABI. Bits-capable scalars travel as exact typed bits; structural Index ingress uses its canonical integer record. Source-visible DRAM address bits are explicit environment/binding inputs, never Python object IDs. The invocation address table maps backing IDs to supplied base-address bits; a view offset uses the declared address arithmetic. Reference/target comparison must use matched allocation responses or an explicit virtual-address adapter. A slot with nonzero padding or wrong byte count rejects before execution.

Empty aggregates have `Bits(0)`: their canonical hex is the empty string and their portable byte slot has length zero. Their logical cells, bounds, initialization, lifetime and backing identity still exist. Reads/writes can therefore perform logical checks or effects without a physical byte access. Keep logical coordinate maps alongside byte views; two zero-byte elements cannot be distinguished by byte offset alone. Never divide by a zero slot width or infer disjoint logical objects from empty address intervals. Target routes erase only the zero data wires, retaining required validity/control state; a foreign ABI that cannot represent this must report a scoped capability error.

A session records semantic interface/state-schema digests, backing/resource generations, initialized cells, numeric/profile IDs and explicit RNG states. `prepare` acquires exclusive session ownership; success/fault/cancel releases it only after the protocol declares quiescence. `reset` waits for or cancels/drains outstanding obligations before installing reset images. An observation timeout leaves ownership held by the resumable invocation. Hardware partial writes remain incomplete outputs; a host cannot relabel them as a successful result.

## Diagnostics and conformance fixtures

Diagnostic fields are `code`, `phase`, `severity`, `message`, `primary`, `related`, `obligation`, `repair`, and `reproduction`. `primary` contains source-unit digest plus half-open UTF-8 byte offsets; presentation converts to character columns using the frozen line map. Related locations carry roles such as declaration, instantiation and conflicting access. Codes use a stable namespace (`SOURCE`, `BIND`, `TYPE`, `EFFECT`, `LIFETIME`, `NUMERIC`, `PROTOCOL`, `HOST`, `ARTIFACT`, `TARGET`, `VENDOR`, `INTERNAL`) and a named rule, never a source-line number. Messages may improve without changing rule identity. A builder without source has generated origin plus instantiation chain; it does not fabricate a file span.

Define `spatial.fixture/1` with fields `id`, `families`, `stage`, `source_bundle`, `meta`, `profile`, `bindings`, `environment`, `expected`, `oracle`, `variations`, and `provenance`. `expected` is a tagged union: diagnostic records; exact output bits plus ordered effects; allowed finite trace graph plus terminal classification; canonical artifact bytes/hash; or target evidence constraints. The `oracle` names hand derivation, independent algorithm, pinned upstream vector, or separately validated protocol model. Shared simulator/checker functions cannot supply their own independent expected answer.

Every fixture has at least a positive case and a distinguishing negative/boundary variation, unless intrinsically a failure-only regression. Trace comparison projects to declared observable events while preserving causal predecessors and terminal/progress requirements. Do not compare only final values, require a single canonical schedule from every backend, or accept an arbitrary prefix as a completed result. Bounded interleaving exploration records bounds and fairness assumptions. Hardware report parsers retain raw report hashes and separate requested, estimated, synthesized and implemented values.

The conformance manifest maps every F01–F18 family and G01–G18 gate to fixture IDs and implementation stages. A check rejects orphan features, duplicate IDs, missing oracle provenance and support claims lacking their required stage. This accounting checks references; it cannot certify expected values. Numeric vectors, scheduler models and source-level counterexamples receive independent review.
