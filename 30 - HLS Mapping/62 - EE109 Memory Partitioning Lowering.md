# EE109 Memory Partitioning Lowering

Citation roots:

- `research/` means `/Users/david/Documents/Spatial Research/`.
- `spatial/` means `/Users/david/Documents/David_code/spatial/`.

This note defines the Wave 1 HLS lowering policy for the EE109 memory subset. The selected MVP is narrow by design: the plan names local memory lowering, dense DRAM transfers, and a `par`-driven partitioning subset as blocking for EE109, while also saying to start from rule-based partitioning rather than the full Spatial banking search (`research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:72-76`). D-07 recommends an HLS-first partition planner over complete, cyclic, block, reshape, duplicate, and binding choices, and rejects default reuse of arbitrary Spatial alpha/N/B banking (`research/20 - Research Notes/50 - Decision Records/D-07.md:48-81`).

## Dense transfers: load/store/getMem/getMatrix/setMem.

Dense local loads are represented as `DenseTransfer(dram, local, isLoad = true)` from the `LocalMem1` through `LocalMem5` load methods, and LineBuffer has a 1-D DRAM load helper that also stages `DenseTransfer` (`spatial/src/spatial/lang/types/Mem.scala:51-80`, `spatial/src/spatial/lang/types/Mem.scala:87-120`, `spatial/src/spatial/lang/LineBuffer.scala:29-31`). Dense stores from local memory to DRAM are represented as `DenseTransfer(..., isLoad = false)` on `DRAM1` and `DRAM2`; Lab2 FSM uses `dram(0::32) store bram`, and Lab3 stores `lineOut` through `imgOut(r, 0::C par 16) store lineOut` (`spatial/src/spatial/lang/DRAM.scala:90-104`, `spatial/src/spatial/lang/DRAM.scala:122-134`, `spatial/test/spatial/tests/ee109/Lab2Part3BasicCondFSM.scala:28-30`, `spatial/test/spatial/tests/ee109/Lab3.scala:74-78`).

Dense slicing is a memory alias, not a new allocation: range `apply` overloads stage `MemDenseAlias`, and the IR records sparse rank, raw rank, and aliases back to the original memory (`spatial/src/spatial/lang/types/Mem.scala:125-145`, `spatial/src/spatial/node/HierarchyMemory.scala:40-70`). Dense transfer effects are directional: stores write the DRAM, while loads write the local memory (`spatial/src/spatial/node/DenseTransfer.scala:17-19`, `spatial/src/spatial/node/DenseTransfer.scala:34-47`). For Wave 1 HLS, lower dense transfers as explicit loops over the selected dense range. Apply `PIPELINE II=1` to the innermost transfer loop when the memory plan has enough ports; otherwise leave the pragma off and let the C++ stay functionally correct.

Host `setMem` stages `SetMem(dram, data)`, and host `getMem` allocates a flat tensor of `dram.dims.prodTree`, stages `GetMem`, and returns the tensor (`spatial/src/spatial/lang/api/TransferAPI.scala:37-45`). `setMem` for a matrix delegates to the matrix's flat `data`, and `getMatrix` wraps `getMem(dram)` with `dram.dim0` and `dram.dim1` (`spatial/src/spatial/lang/api/TransferAPI.scala:60-64`). In the HLS ABI, `setMem` is host-harness initialization of the `m_axi` buffer before kernel launch; `getMem` and `getMatrix` are host-harness reads after kernel completion.

Unsupported in Wave 1: sparse gather/scatter aliases and `SparseTransfer`, because the selected corpus only requires dense aliases and dense transfers. The existing language does expose sparse DRAM aliases and `gather`, so rejecting them must be an explicit diagnostic, not a parser failure (`spatial/src/spatial/lang/DRAM.scala:65-87`, `spatial/src/spatial/lang/types/Mem.scala:69-72`).

## Partitioning policy for par

Start with rule-based array partitioning from observed `par` dimensions, not full banking search. The current compiler dispatches SRAM and LineBuffer through `ExhaustiveBanking`, and RegFile, LUT, and Reg through `FullyBanked` (`spatial/src/spatial/traversal/MemoryAnalyzer.scala:125-132`). `MemoryConfigurer` then explores banking views, N strictness, alpha strictness, and dimension duplication before finalizing a plan (`spatial/src/spatial/traversal/banking/MemoryConfigurer.scala:21-48`, `spatial/src/spatial/traversal/banking/MemoryConfigurer.scala:55-83`). That is more general than the EE109 MVP needs. D-07 explicitly recommends pruning before solving and limiting the normal HLS planner to HLS-lowerable partition forms (`research/20 - Research Notes/50 - Decision Records/D-07.md:48-81`).

Rules for Wave 1:

1. Discover `par` from selected loops and dense ranges. `Series` stores the `par` factor, and counter-chain metadata exposes whether a controller will unroll (`spatial/argon/src/argon/lang/Series.scala:12-25`, `spatial/src/spatial/metadata/control/package.scala:986-992`).
2. For each local memory access inside a `par p` loop, partition the accessed dimension enough to supply `p` lanes. Use complete partition when the static dimension is small and equals or is below the lane count, especially for Lab3's `Kh = 3` and `Kw = 3` reductions (`spatial/test/spatial/tests/ee109/Lab3.scala:7-8`, `spatial/test/spatial/tests/ee109/Lab3.scala:56-67`).
3. For 1-D row staging buffers accessed by a dense transfer with `par p`, use cyclic partition by factor `p` on the column dimension. Dense transfer lowering already extracts transfer `pars` from the DRAM alias and checks last-dimension packing and burst limits (`spatial/src/spatial/node/DenseTransfer.scala:51-63`, `spatial/src/spatial/node/DenseTransfer.scala:80-98`).
4. For RegFile and LUT used in fully parallel stencil reductions, use complete partition on all accessed stencil dimensions. The current `FullyBanked` strategy effectively chooses the staged dimension count as the bank count for its selected axes (`spatial/src/spatial/traversal/banking/FullyBanked.scala:275-283`), which supports this small-array policy without requiring the old search.
5. For LineBuffer, partition rows complete and columns cyclic by the row-load `par`. The current banking path treats line buffers specially by selecting hierarchical banking with the last dimension segregated, and an existing no-conflict shortcut auto-banks line buffers by rows plus stride depth (`spatial/src/spatial/traversal/banking/MemoryConfigurer.scala:25-32`, `spatial/src/spatial/traversal/banking/ExhaustiveBanking.scala:206-210`).
6. If two concurrent accesses still require more ports than the rule can provide, emit an unsupported-diagnostic with the memory name, access site, `par` factor, and proposed partition. Do not silently fall back to arbitrary alpha-vector banking; D-07 reserves arbitrary `ModBanking(N, B, alpha, axes, P)` for explicit escape-hatch use (`research/20 - Research Notes/50 - Decision Records/D-07.md:117-128`).

## Lab3 memory plan with LineBuffer and RegFile shift-register behavior

Lab3's selected memory structure is fixed: `img` and `imgOut` are 2-D DRAMs, the input matrix is copied into `img` with `setMem`, `lb` is `LineBuffer[T](Kh, Cmax)`, `sr` is `RegFile[T](Kh, Kw)`, `kh` and `kv` are 3 by 3 LUT kernels, and `lineOut` is a 1-D SRAM row buffer (`spatial/test/spatial/tests/ee109/Lab3.scala:20-36`). The row loop loads a dense row slice into the LineBuffer, then the column loop resets `sr` at column zero, shifts each `lb(i, c)` into `sr(i, *)`, performs two parallel 3 by 3 reductions, writes `lineOut(c)`, and stores the row back to `imgOut` (`spatial/test/spatial/tests/ee109/Lab3.scala:38-78`).

LineBuffer lowering:

- Represent `lb` as a 2-D circular row buffer with `Kh` visible rows and `Cmax` columns. Current IR records `LineBufferNew(rows, cols, stride)` with `dims = Seq(rows, cols)`, and the runtime model maintains `bufferRow`, `readRow`, `stride`, and row-swapping state (`spatial/src/spatial/node/LineBuffer.scala:7-14`, `spatial/emul/src/emul/LineBuffer.scala:14-25`).
- Lower `lb load img(r, 0::C par lb_par)` as a dense row-copy loop from `img[r * C + c]` into the active LineBuffer write row. Current dense transfer lowering builds counters from sparse lengths and `pars`, and rejects upper-dimension parallelism above 1 (`spatial/src/spatial/node/DenseTransfer.scala:80-98`).
- Lower `lb(i, c)` reads as row-window reads at stencil row `i` and column `c`; current LineBuffer nodes separate `LineBufferRead` and `LineBufferEnq`, and the runtime `apply` uses bank and offset to read from the shifted row window (`spatial/src/spatial/lang/LineBuffer.scala:16-31`, `spatial/emul/src/emul/LineBuffer.scala:31-60`).

RegFile shift-register lowering:

- Represent `sr` as `T sr[Kh][Kw]` with complete partition on both dimensions for Lab3. `RegFile2.apply(i, *)` returns a `RegFileView` along axis 1, and `<<=` stages `RegFileShiftIn` with that axis (`spatial/src/spatial/lang/RegFile.scala:165-175`, `spatial/src/spatial/lang/RegFile.scala:203-205`, `spatial/src/spatial/node/RegFile.scala:50-56`).
- Implement `sr(i, *) <<= lb(i, c)` as a shift across the `Kw` dimension for each row `i`: move existing entries toward higher column indices and insert the new line-buffer value at the first position.
