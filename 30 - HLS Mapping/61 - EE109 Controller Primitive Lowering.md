# EE109 Controller Primitive Lowering

## Selected controller subset: Accel, Foreach, Sequential.Foreach, Pipe, Reduce, FSM

This note owns controller and primitive lowering only. Memory-system representation, DRAM/SRAM/LUT/RegFile/LineBuffer layout, banking, and dense transfer mechanics remain with the Memory Agent. The selected controller subset is the Wave 1 controller scope in the EE109 HLS MVP plan, which assigns the lowering agent `Accel`, `Foreach`, `Sequential`, `Pipe`, `Reduce`, `FSM`, `mux`, and arithmetic (`/Users/david/Documents/Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:123-124`) and asks the lowering map to cover these control rows plus operators (`/Users/david/Documents/Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:251-263`).

- `Accel`: selected because Lab2 FSM and Lab3 both wrap hardware work in `Accel` (`/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab2Part3BasicCondFSM.scala:11-29`, `/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab3.scala:25-76`). Current DSL lowering stages `AccelScope(stageBlock { scope; void })` (`/Users/david/Documents/David_code/spatial/src/spatial/lang/control/AccelClass.scala:17-18`).
- `Foreach`: selected for Lab3 row iteration, shift-register update, diagnostic nested loops, and output store scope (`/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab3.scala:38-45`, `/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab3.scala:74-75`). Current DSL lowering creates a `CounterChain`, binds iterators, and stages `OpForeach` (`/Users/david/Documents/David_code/spatial/src/spatial/lang/control/ForeachClass.scala:26-32`).
- `Sequential.Foreach`: selected for Lab3's per-column loop (`/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab3.scala:41-73`). Current `Sequential` carries `Some(Sequenced)` in `CtrlOpt`, and `Directives` exposes the `.Foreach` builder used by `Sequential.Foreach` (`/Users/david/Documents/David_code/spatial/src/spatial/lang/control/Control.scala:9-18`, `/Users/david/Documents/David_code/spatial/src/spatial/lang/control/Control.scala:49-56`).
- `Pipe`: selected for Lab3's single-cycle reset region (`/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab3.scala:42`). Current `Pipe` carries `Some(Pipelined)`, optional user II, and MOP/POM flags (`/Users/david/Documents/David_code/spatial/src/spatial/lang/control/Control.scala:22-33`).
- `Reduce`: selected for Lab3's horizontal and vertical Sobel accumulations (`/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab3.scala:53-68`). Current `Reduce` stages map, load, reduce, and store blocks into `OpReduce` (`/Users/david/Documents/David_code/spatial/src/spatial/lang/control/ReduceClass.scala:38-52`).
- `FSM`: selected for Lab2Part3BasicCondFSM (`/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab2Part3BasicCondFSM.scala:15-26`). Current `FSM` stages not-done, action, and next-state lambdas into `StateMachine` (`/Users/david/Documents/David_code/spatial/src/spatial/lang/control/FSM.scala:18-23`).

## Lab3 nested Reduce and par policy

Lab3 creates two explicit scalar accumulators, `horz` and `vert`, then runs two nested reductions over `Kh` and `Kw`, with both dimensions marked `par` in the selected source (`/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab3.scala:53-68`). The source sets `Kh = 3` and `Kw = 3`, so the selected case is a static 3-by-3 integer reduction (`/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab3.scala:7-8`).

Policy:

1. Lower each Sobel direction as an independent two-level integer reduction: multiply each selected `sr(x, y)` value by the corresponding kernel value, reduce across `Kw`, then reduce across `Kh`, and finally assign the explicit accumulator. The current `Reduce` implementation supports an explicit `Reg` accumulator path and a constant-zero implicit accumulator path, both used by Lab3's outer and inner reductions (`/Users/david/Documents/David_code/spatial/src/spatial/lang/control/ReduceClass.scala:55-87`).
2. Treat `par` as controller lane parallelism, not as a memory layout directive. `Series.par` stores a lane factor in the series (`/Users/david/Documents/David_code/spatial/argon/src/argon/lang/Series.scala:12-25`), `Counter.from` carries that factor into `CounterNew` (`/Users/david/Documents/David_code/spatial/src/spatial/lang/Counter.scala:14-28`), and `Reduce` binds iterator metadata using `ctr.ctrParOr1` (`/Users/david/Documents/David_code/spatial/src/spatial/lang/control/ReduceClass.scala:38-45`).
3. For the selected static `Kh par Kh` and `Kw par Kw`, emit fully unrolled lane loops or cloned scalar expressions with `#pragma HLS UNROLL factor=3` at each dimension. Combine lanes through an explicit deterministic reduction tree. This matches the current unrolling note that `OpReduce` becomes `UnrolledReduce` or a `UnitPipe`, and that the reduction tree substitutes identity values or propagates valid bits depending on identity availability (`/Users/david/Documents/Spatial Research/10 - Spec/40 - Compiler Passes/80 - Unrolling.md:154-169`).
4. Keep the surrounding `Sequential.Foreach(0 until C)` sequential in the MVP. The selected source nests the reductions inside that controller (`/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab3.scala:41-73`), and current `Sequential` explicitly selects the `Sequenced` schedule (`/Users/david/Documents/David_code/spatial/src/spatial/lang/control/Control.scala:49-56`).
5. Do not infer RegFile/LUT banking, array partitioning, or line-buffer ports in this artifact. The controller lowering should request enough read ports for the lane-parallel body and let the Memory Agent decide whether the backing object can satisfy them.

## Deferrals: Fold/MemReduce unless selected, floating point, FMA, OneHotMux policy

- `Fold` and `MemReduce`: defer unless a selected EE109 example requires them. The MVP plan marks Fold/MemReduce conditional rather than part of the initial selected path (`/Users/david/Documents/Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:58-62`, `/Users/david/Documents/Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:79-85`). Current `OpMemReduce` has separate map and reduce counter chains and an inner stage with four sub-blocks, so it is not a trivial extension of scalar `Reduce` (`/Users/david/Documents/David_code/spatial/src/spatial/node/Control.scala:78-101`).
- Floating point and broad fixed-point policy: defer. The MVP plan explicitly defers floating-point and transcendental precision choices for the selected EE109 floor (`/Users/david/Documents/Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:87-97`). Lab3 is generic in `T: Num`, but the selected local test constructs an integer image and calls `convolve(image)` from that integer host value (`/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab3.scala:11-23`, `/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab3.scala:81-91`).
- FMA: defer. The MVP plan lists FMA fused-versus-unfused semantics as deferred (`/Users/david/Documents/Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:87-93`). Current notes record that ScalaGen emits `FixFMA` as multiply then add, and that fixed-point low bits can differ from fused hardware behavior (`/Users/david/Documents/Spatial Research/10 - Spec/20 - Semantics/60 - Reduction and Accumulation.md:50-64`).
- `OneHotMux` policy: defer explicit `oneHotMux`. The selected Lab2 source uses a nested conditional value, while its comment mentions a bound one-hot mux path (`/Users/david/Documents/David_code/spatial/test/spatial/tests/ee109/Lab2Part3BasicCondFSM.scala:24`). Spatial exposes `oneHotMux` as a separate API (`/Users/david/Documents/David_code/spatial/src/spatial/lang/api/MuxAPI.scala:26-32`), and the `OneHotMux` node has special static-true rewrite behavior including a warning when multiple selects are statically true (`/Users/david/Documents/David_code/spatial/src/spatial/node/Mux.scala:19-37`). The plan already defers the multi-true policy (`/Users/david/Documents/Spatial Research/90 - Meta/plans/2026-06-25-ee109-hls-mvp-plan.md:91-97`).
